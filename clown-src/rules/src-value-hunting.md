# SRC 价值与类型矩阵

先遵守 [研究边界](security-research-context.md)。本文件帮助选择风险假设，不要求对每个接口执行全部探针；节奏和完成条件见 [范围工作流](dig-scope-workflow.md)。

## 1. 价值判断

关注实际跨身份/跨租户访问、认证绑定、权限提升、数据完整性与执行边界。租户管理员的本职访问不是漏洞，租户管理员能越到平台权限才需分析。HTTP 200、配置字符串、空列表和组件指纹不是影响证明。

### 1.1 优先级

从当前真实业务面中选择影响大且可安全验证的假设；有身份时先理解对象关系，没有身份时分析匿名入口。注入、SSRF、XSS、执行链和逻辑缺陷均可成为重点，不固定先后顺序，也不把某类型的报告数量当绩效。

## 2. 链式影响

文件、配置、认证或响应线索可能关联更深的数据流；有证据且在允许范围内再追踪。证明漏洞不要求转钱、改真实账号或扩大敏感数据提取。凭证疑似泄露应保护原值；只有允许的服务与身份才可进行最小验证，无法验证则说明前提而非伪称可用。

SRC 默认排除 CORS，见 [CORS 偏好](cors-vuln-report-priority.md)。正式报告标准见 [报告格式](vuln-report-format.md)。

## 3. 按入口选类型

| 入口/数据流 | 检查问题 | 专题 |
|---|---|---|
| 列表、详情、附件、导出 | 身份与对象/租户是否绑定 | [IDOR](../知识库/idor-test.md) |
| 登录、重置、改绑、换票、2FA | 服务端校验、状态与身份绑定 | [认证](../知识库/authbypass-test.md) |
| 查询、排序、表达式、模板 | 不可信输入是否进入解释器 | [注入](../知识库/injection-test.md) |
| URL、代理、导入、预览 | 目标校验与出站访问边界 | [SSRF](../知识库/ssrf-test.md) |
| 可控文本、回显、富文本 | 编码、上下文与脚本执行 | [XSS](../知识库/xss-test.md) |
| 上传、下载、文件名 | 存储路径、解析与权限 | [上传](../知识库/file-upload-test.md)、[路径](../知识库/path-traversal-lfi-test.md) |
| 序列化、命令、危险转换 | 可控输入至执行 Sink | [反序列化](../知识库/deserialization-test.md) |
| 订单、审批、库存、状态 | 权限、跳步、并发与事务 | [逻辑](../知识库/logic-test.md)、[竞态](../知识库/race-condition-test.md) |
| 凭证、调试或配置暴露 | 真伪、范围、可证明影响 | [信息泄露](../知识库/info-leak-test.md) |
| GraphQL、XML、WebSocket、OAuth | 对应协议的鉴权与解析边界 | 按 [知识索引](../知识库/README.md) 选模块 |

未列出的入口可按其实际信任边界分析；清单不封闭能力，也不扩大测试授权。

## 4. 参数与证据

记录完整请求形态中的相关 query/body/header/path 字段，别只看首页或第一个参数。选与技术栈相符的最小测试，对照正常响应，复核错误、内容或时序差分。WAF 拦截本身不证明漏洞，也不是扩大探针量的理由。

## 5. 交付

用简洁证据说明基线、改变、结果和影响；未验证/无入口/缺前提明确区分。没有稳定结果就不能把猜测标为已确认。禁止以文件数量、探活数量或重复差分填充进度。
