# 中文 SRC 报告

正式报告面向安全评审，说明做成了什么、如何复核、影响及修复。遵守 [研究边界](security-research-context.md)；用户或 SRC 的报告模板优先。

## 一、正文格式

默认用以下字段。标题、目标 URL、等级各占一行；各大块用单独一行全角 `＃` 分隔，描述/危害标签后换行。文件名用漏洞标题的安全文件名形式，放任务 `报告/`，按接收方要求选择换行格式。

| 字段 | 内容 |
|---|---|
| 漏洞标题 | 目标 + 实际突破的权限/业务边界。匿名需有真正不携带有效凭证的复现；有会话跨对象称越权，不能只凭历史会话状态判断。 |
| 目标网站URL | 实际人可打开的入口；不包含凭证或敏感查询值。 |
| 漏洞等级 | 优先适用 SRC 定级标准；依据已证明影响、权限前提及利用条件。没有依据时说明暂定，不为提高等级追加高影响操作。 |
| 漏洞描述 | 用第一人称直接说明原身份、操作和实际结果。来源是 JS/文档时附来源路径或脱敏 URL；秘密只用占位符。 |
| 漏洞危害 | 区分已证明影响与条件性推断。举受控或脱敏样例；可读权限不等于可写/可退款，未执行不编造成执行。 |
| 涉及接口清单 | 列实际复现涉及的完整路径、METHOD 与来源；敏感参数脱敏，不把首页或抄参文件冒充漏洞接口。 |
| 复现步骤 | 编号给出必要前提、基线、测试输入及实际结果。每步一个最小必要请求/命令，说明跨步骤变量来源；保留足够脱敏响应证据使评审能核实，不堆无关请求头。 |
| 修复建议 | 对准根因和共享检查点，给出可实施的校验/隔离方案及相关回归点。 |

请求中 Host 与请求行匹配；有 body 时注明实际 Content-Type。让客户端计算 Content-Length，避免手写失效长度。Cookie、Token、密码、私钥及个人信息使用显式占位符；替换步骤说明在前提里。脱敏报告不应冒称无需补充任何输入即可直接复制运行。

## 二、证据与收录

- 确认的中危及以上 SRC 发现及时写报告；相同根因和接口增补原篇，不按换一个 ID 重复交。
- 默认不单独提交 CORS、仅缺安全头/版本/公开信息、未形成影响的上传下载、单纯 HTTP 200 等；用户要求完整审计时可单列低风险与待验证项，不隐瞒覆盖缺口。
- 疑似凭证泄露不等于凭证可用。仅在允许的服务与受控权限内做最小验证；不为证明泄露而转钱、读取大量数据或进入范围外系统。未验证时明确说明。
- 匿名、越权、可批量和执行能力各需对应证据；不能用一条成功响应推断无限权限。
- 报告与知识库不包含秘密实值。必要原始证据留在用户指定的受控位置，交付只提供脱敏引用。
- 清理只按 [目录规则](desktop-task-folder.md)，不由「有无报告」推导删除整个任务目录。
