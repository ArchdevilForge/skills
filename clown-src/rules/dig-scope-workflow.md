# 黑盒范围与执行

先遵守 [研究边界](security-research-context.md)。本文件管理范围、节奏和完成条件；类型细节看 [价值矩阵](src-value-hunting.md)，发现交付看 [报告格式](vuln-report-format.md)。

## 0. 选择模式

- **锁面**：用户给定站点、接口、文档或清单，只测试该范围。业务流带出的 host/path 可作为候选，不凭跳转关系自动视为授权。
- **范围内探索（自由跳）**：用户允许在明确 SRC 范围内发现资产。只有品牌名时先核对范围页；不清楚时先公开资料整理，不默认测试所有关联公司。
- 当次指定的优先资产、排除项、请求预算、时限和停止条件优先于默认顺序。

### 0.1 锁面口径

同 host 不同 path/端口可能是不同业务；不同 host 也可能是同一资产簇。按业务与明确范围判断，不能把入口字符串当完整清单，也不能偷偷变为全集团扫描。

### 0.2 自主推进

范围内、预算内且有新证据时继续，不在每一步索要「继续」。缺少关键权限/对照对象时标阻塞并处理独立可做部分；范围不明、高影响操作或无安全替代时暂停相关路径。

## 1. 范围内探索

### 1.0 新任务与续跑

已有任务目录时读队列、覆盖记录和报告，避免重测。新任务仅在需要产物时按 [目录规则](desktop-task-folder.md) 建目录。

### 1.0.1 一种子闭环

默认：选一个已在范围内的种子 → 搜索 → 去重、核实范围与存活 → 分析有效业务面 → 记录完成/阻塞 → 再选下一条。搜索服务于分析，不为囤积条数连续扩面。用户指定不同顺序或现场证据表明应换线时，说明原因即可调整。

### 1.1 种子选择

优先用户点名资产和 SRC 明列域名，其次有明确授权依据的新业务面。按风险和本轮预算安排，不以固定条数冒充覆盖，也不要求无限补齐关联公司。

### 1.1.1 新根域回灌

有价值的新 host 可归并为业务簇候选并记录来源。根域归约不扩展授权；范围核实后再加入 pending。去重后有新证据才重访已完成种子。

### 1.2 存活筛选

优先已有资产与被动资料，再做允许范围内的低成本探活。401/403/登录页不是死站；无解析、停放、重复静态壳可标 cold。一次超时不能证明服务永久不可达。

### 1.3 续跑与饱和

新 path、端口、应用或有证据的构建变化可重新分析；相同镜像和同一已报告问题不算新增。队列处理完即交付本轮结果；没有新增证据时不自动随机搜索。持续研究另由用户目标和预算限定。

### 1.4 队列与结束

多资产任务记录：目标/范围依据、pending/doing/done/blocked/cold、下一验证动作和证据位置。单接口任务无需完整队列。

结束条件：请求范围处理完、预算到达、连续检查无新增证据且没有有效下一步、关键前提不可用、或用户叫停。报告覆盖与未测部分；pending 不意味着必须无界续跑。

### 1.5 工具配额

遇到限流停止重复请求，遵守服务重试时间。可分析已有材料；不通过轮换账号绕过限流，不假定本机有备用账号。需要额外费用或配置时先说明。

### 1.6 扩面

只扩展到本轮确认范围内且有证据支持的新面。资产发现、报告数量和日志不是进度目标；新结论、证伪、接口/数据流理解才是。

## 2. 避免空转

相同登录码、重复路径、偶发超时或已证伪假设不应反复喷探针。判断是需要补上下文、换方法、换范围内目标，还是结束本轮；没有报告不等于没有进展。

### 2.1 深挖优先

优先完成当前高价值假设的证据链，再扩面；不能为升级定级实施更高影响的操作。

### 2.1.4 限流

按 §1.5 处理；已有材料不足时交付阻塞，不空撞。

### 2.1.5 协作

按实际任务需要拆分独立 host/模块；明确各线程的范围、证据和预算，避免重复测绘、重复写同一文件。协作工具服从宿主能力与隔离协议，不默认启动线程。

## 3. 去重与归属

### 3.1 去重

按 host、port、path 与业务身份去重。静态库/CDN/第三方只记录依赖，不自动测试。

### 3.1.1 覆盖记录

已完成的同一业务面跳过；新 path、端口或应用可记录为增量。已报告同一问题扩充原证据，不重复当新洞。

### 3.2 归属

### 3.2.0 范围依据

集团持股、证书、标题和备案仅辅助归属判断；测试范围以用户明确授权及适用 SRC 范围为准。存疑目标先待确认，不以「像一家」或「百分百控股」直接开测。

### 3.2.1 已有依据

范围页或明确授权已覆盖的资产无需反复查同一归属信息。

### 3.2.2 存疑依据

用公开资料交叉核实，仍不明确则记候选并暂停该资产测试。工具不可用不降低范围标准。

### 3.3 同构面

同构镜像选代表验证；其余只检查与风险相关的差异。相同首页不证明鉴权相同；没有实质差异不重复全矩阵。

## 4. 单站分析

### 4.0 理解业务

识别用户角色、核心对象、权限/资金/状态字段与匿名可达边界。只记有助于验证的信息，不强制生成长前置报告。

### 4.1 接口清单

从页面、JS、API 文档和实际请求中整理 METHOD、path、参数、鉴权与数据流。关联有价值的 chunk、sourcemap、隐藏路由和签名逻辑；凭证仅作为敏感证据，不自动用来扩大权限或进入第三方系统。

纯 API 或 JS 不可用时用已有文档、抓包和响应链接补充；不为抽干前端阻塞所有分析。

### 4.1.1 登录页

先识别后面的业务 API 与自家认证链，不在验证码、口令字典和重复登录壳上耗费预算。第三方 IdP 不因业务重定向而进入范围。已有会话使用受控对象作对照。

### 4.1.2 同一登录码

区分无业务数据的登录拒绝、有结构但为空的响应、稳定差分与偶发错误。相同拒绝且无新线索时停止该假设；不靠重复请求直到偶发异常来证明漏洞。

### 4.1.3 响应线索

新对象关系、附件/导出、角色及内部 host 可补入清单；验证仍限允许对象和数据最小化。列表的权限检查不能代表子资源也正确。

### 4.2 类型覆盖

依照实际入口选 [类型矩阵](src-value-hunting.md)，记录已验证、证伪、无入口或缺前提。不为凑矩阵构造不存在的参数，也不把每个类型变成无条件必打。

### 4.2.1 注入、SSRF、XSS、执行边界

按真实参数、回显、URL 处理和危险 Sink 选择专题。比较正常基线与最小探针，复核差分稳定性；使用受控目标/回连和隔离环境，不以读取元数据凭证或真实执行破坏动作作为完成门槛。

### 4.2.2 认证与会话

验证登录、重置、改绑、换票、2FA 的状态绑定和服务端检查。用受控身份复现；写入前确定可恢复，不更改真实他人账号。现有用户会话的保护见研究边界。

### 4.2.3 对象与逻辑

画清列表→详情→附件/导出/审批关系，使用允许的对照身份/对象验证隔离。没有对照账号时可分析请求和代码并报告前提缺口，不默认枚举邻号或修改真实他人数据。并发和资金流程优先在测试环境验证。

### 4.3 本轮完成

相关数据流和假设已处理，结果有证据，未测/阻塞有原因，即可结束当前站。高价值未闭合线索在安全范围与预算内继续；不要求把每个中危都升级才准换站。确认发现按报告格式交付，无发现不造空报告。

### 4.4 站级节奏

范围 → 业务/接口 → 风险假设 → 最小验证 → 证据或证伪 → 下一范围内任务或结束。只有用户要求经验沉淀时才读 [知识维护](hunt-iter.md)。
