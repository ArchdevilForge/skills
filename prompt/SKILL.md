# Prompt editing

理解用户要达到的结果，然后交付最短且足够明确的指令。简单改写直接给成品；只有缺失信息会改变任务、权限或验收时才问。

- 明确本轮结果、必要上下文和完成条件。保留用户真实约束，不添加角色、步骤和禁令凑模板。
- 找矛盾、失效路径、未定义的结束条件、过宽权限及无关前置阅读。只修影响实际行为的部分。
- 沿用现有格式；自然语言、Markdown、XML 或 schema 按下游需要选择。XML 不是默认必填结构。
- 工程任务的完成条件按影响选择相关检查；外部副作用给明确边界，不把所有动作都变成审批点。
- 推理留给模型内部，交付可检查的结论和必要依据；不要求输出私有思维过程。

需要复杂契约或格式样例时读 [参考](prompt-reference.md) 或 [示例](examples.md)，不把示例步骤视为所有任务必跑。技能文件的结构/触发优化见 [技能编写路由](references/skill-authoring.md)。

输出改写版；用户要求审计时附发现与理由，否则只说明重要变化或仍需确认的一点。不为每次小改强制打分、XML 七段、风险表和三个版本。
